# Module `tri::i18n` — langues

Toutes les chaînes destinées à l'utilisateur — interface, ligne de commande, messages
d'erreur du moteur, lignes du panneau des métadonnées — sont traduites (demandé le
17/10/2026, choix technique laissé à Claude). Langues : **français** (référence) et
**anglais**.

## Choix : Fluent

[Fluent](https://projectfluent.org) (Mozilla), crate `fluent-bundle` (MIT OR Apache-2.0,
dépôt actif, dernière modification le 27/09/2026). Préféré à `rust-i18n` (plus actif, mais
sans règles de pluriel) parce qu'il **choisit la forme du pluriel selon la langue** : en
français 0 et 1 sont au singulier (« 0 image », « 1 image »), en anglais seul 1 l'est.
Langue du système : `sys-locale` (1Password, MIT OR Apache-2.0).

## Principe

- Le code ne contient que des identifiants : `t!("cache-cleared")`,
  `t!("status-images", n = 3, raws = 0, filter = f)`. Les textes sont dans des
  catalogues `.ftl` embarqués dans le binaire (`include_str!`) : `locales/fr.ftl`,
  `locales/en.ftl` pour le moteur et la ligne de commande, `gui/locales/*.ftl` pour
  l'interface (ajoutés par `tri::i18n::register`).
- Repli : un identifiant absent d'une langue s'affiche en français ; absent partout, il
  s'affiche tel quel (les tests l'empêchent).
- Nombres entiers : passés tels quels, ils choisissent le pluriel. Décimaux : mis en
  forme avant (`i18n::decimal` : virgule en français, point en anglais). Largeurs de
  colonnes (ligne de commande) : mises en forme en Rust, puis passées en texte.
- Marques d'isolement Unicode désactivées (`set_use_isolating(false)`) : les polices de
  l'interface ne les ont pas.

## Pièges de Fluent rencontrés

- **Espaces en tête et en fin de valeur supprimés** : « · mode visuel » collait au texte
  précédent, « ou » perdait ses espaces. Les valeurs concernées s'écrivent en littéral :
  `{ " " }· mode visuel`, `{ " ou " }`.
- Les **identifiants** n'acceptent pas les points : l'action `core.nav.next` a pour
  libellé `action-core-nav-next`.
- Une valeur sur plusieurs lignes (mode d'emploi de la ligne de commande) perd
  l'indentation commune ; ses lignes ne peuvent pas commencer par `[`, `*` ou `.`.

## Langue choisie

`[i18n] language = "auto"` (défaut : langue du système, l'anglais si elle n'est pas
disponible), `"fr"` ou `"en"`. La configuration étant elle-même lue dans une langue,
l'interface et la ligne de commande prennent d'abord la langue du système (messages
d'erreur de lecture de la configuration), puis celle de la configuration.

## Raccourcis

Les noms de touches (« Flèche gauche » / « Left arrow », « Maj+ » / « Shift+ ») sont
affichés dans la langue de l'interface et **lus dans toutes les langues** dans `[keys]` :
une configuration écrite en français reste valable si la langue change.

## API

| Élément | Rôle |
|---|---|
| `t!(id)`, `t!(id, nom = valeur, …)` | texte traduit (moteur : `crate::t!`, interface : sa propre macro `t!`, qui ajoute d'abord ses catalogues) |
| `translate(id, args)`, `translate_in(langue, id, args)` | idem, sans macro ; dans une langue donnée (noms de touches) |
| `set_language`, `language`, `Language::system`, `LanguageSetting::resolve` | langue |
| `register(langue, source)` | ajoute un catalogue (l'interface) |
| `decimal(valeur, chiffres)` | nombre décimal à la façon de la langue |
| `has`, `ids`, `engine_catalogs` | tests de complétude |

Restent en français, volontairement : traces de développement (`TRI_GUI_TRACE`), messages
des variables de développement (`TRI_GUI_*`), messages d'invariants internes (`expect`).

## Ajouter une langue

1. `Language` : une variante et son code (`src/i18n.rs`) ; `LanguageSetting` aussi.
2. Copier `locales/fr.ftl` et `gui/locales/fr.ftl` sous le nouveau code, traduire.
3. Ajouter les catalogues aux listes `ENGINE` (moteur) et `CATALOGS` (interface).

Les tests vérifient que chaque catalogue a exactement les identifiants du français.

## Tests

- Moteur (`src/i18n.rs`) : locales reconnues (`fr-FR`, `en_US.UTF-8`), mêmes identifiants
  en français et en anglais sans doublon, pluriels (« 0 image » / « 0 images »).
- Intégration (`tests/i18n.rs`) : chaque `t!("…")` littéral des sources du moteur existe
  dans toutes les langues (lecture des fichiers `.rs`, hors commentaires et hors
  `format!(`), catalogues identiques.
- Interface (`gui/src/i18n.rs`) : idem pour `gui/src`, plus les libellés construits
  (actions, thèmes de l'aide) ; pas de collision avec le moteur. `gui/src/actions.rs` :
  « Shift+P » = « Maj+P », « Left arrow » = « Flèche gauche ».
- Les tests d'interface fixent le français (`[i18n] language = "fr"`) : ils cherchent les
  libellés.
