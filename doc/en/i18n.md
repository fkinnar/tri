# Module `tri::i18n` — languages

All user-facing strings — interface, command line, engine error messages, lines of the
metadata panel — are translated (requested on 2026-10-17, technical choice left to
Claude). Languages: **French** (reference) and **English**.

## Choice: Fluent

[Fluent](https://projectfluent.org) (Mozilla), crate `fluent-bundle` (MIT OR Apache-2.0,
active repository, last change on 2026-09-27). Preferred over `rust-i18n` (more active,
but without plural rules) because it **chooses the plural form according to the
language**: in French 0 and 1 are singular ("0 image", "1 image"), in English only 1 is.
System language: `sys-locale` (1Password, MIT OR Apache-2.0).

## Principle

- The code contains only identifiers: `t!("cache-cleared")`,
  `t!("status-images", n = 3, raws = 0, filter = f)`. The texts live in `.ftl` catalogs
  embedded in the binary (`include_str!`): `locales/fr.ftl`, `locales/en.ftl` for the
  engine and the command line, `gui/locales/*.ftl` for the interface (added by
  `tri::i18n::register`).
- Fallback: an identifier missing from a language is shown in French; missing
  everywhere, it is shown as is (the tests prevent this).
- Integers: passed as is, they select the plural. Decimals: formatted beforehand
  (`i18n::decimal`: comma in French, point in English). Column widths (command line):
  formatted in Rust, then passed as text.
- Unicode isolation marks disabled (`set_use_isolating(false)`): the interface fonts do
  not have them.

## Fluent pitfalls encountered

- **Leading and trailing spaces of a value are stripped**: "· mode visuel" stuck to the
  preceding text, "ou" lost its spaces. The affected values are written as literals:
  `{ " " }· mode visuel`, `{ " ou " }`.
- **Identifiers** do not accept dots: the action `core.nav.next` has the label
  `action-core-nav-next`.
- A multi-line value (command-line usage text) loses its common indentation; its lines
  cannot start with `[`, `*` or `.`.

## Chosen language

`[i18n] language = "auto"` (default: system language, English if it is not available),
`"fr"` or `"en"`. Since the configuration itself is read in some language, the interface
and the command line first take the system language (error messages when reading the
configuration), then the configuration's.

## Shortcuts

Key names ("Flèche gauche" / "Left arrow", "Maj+" / "Shift+") are displayed in the
interface language and **read in every language** in `[keys]`: a configuration written in
French stays valid if the language changes.

## API

| Item | Role |
|---|---|
| `t!(id)`, `t!(id, nom = valeur, …)` | translated text (engine: `crate::t!`, interface: its own `t!` macro, which first adds its catalogs) |
| `translate(id, args)`, `translate_in(langue, id, args)` | same, without a macro; in a given language (key names) |
| `has(language, id)` | the identifier exists in that language's catalogue (no fallback); catalogues read once and kept, as for `translate` (issue #16, 2026-10-22: re-read on each call, the settings search cost 120 ms per frame) |
| `set_language`, `language`, `Language::system`, `LanguageSetting::resolve` | language |
| `register(langue, source)` | adds a catalog (the interface) |
| `decimal(valeur, chiffres)` | decimal number in the language's style |
| `has`, `ids`, `engine_catalogs` | completeness tests |

Deliberately left in French: development traces (`TRI_GUI_TRACE`), messages of the
development variables (`TRI_GUI_*`), internal invariant messages (`expect`).

## Adding a language

1. `Language`: a variant and its code (`src/i18n.rs`); `LanguageSetting` too.
2. Copy `locales/fr.ftl` and `gui/locales/fr.ftl` under the new code, translate.
3. Add the catalogs to the `ENGINE` (engine) and `CATALOGS` (interface) lists.

The tests check that each catalog has exactly the French identifiers.

## Tests

- Engine (`src/i18n.rs`): recognized locales (`fr-FR`, `en_US.UTF-8`), same identifiers in
  French and English with no duplicates, plurals ("0 image" / "0 images").
- Integration (`tests/i18n.rs`): every literal `t!("…")` in the engine sources exists in
  every language (reading the `.rs` files, excluding comments and `format!(`), identical
  catalogs.
- Interface (`gui/src/i18n.rs`): same for `gui/src`, plus the built labels (actions, help
  topics); no collision with the engine. `gui/src/actions.rs`: "Shift+P" = "Maj+P",
  "Left arrow" = "Flèche gauche".
- The interface tests pin French (`[i18n] language = "fr"`): they look for the labels.
